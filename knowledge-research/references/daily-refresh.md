# 每日联网与用户豆包补充

只在前沿研究、就业技能的实际学习日授新课前使用。基础数学、物理、英语等稳定学科不执行每日例行更新；首次选材与发现实质证据缺口仍可检索。依据学习用途分类，不只看关键词：英语语法是 foundational，求职英语是 career；数学基础与前沿机器学习混合时只刷新变化部分。分类、原因和范围写入月计划。

面向职业求职时，先完成 [job-research.md](job-research.md) 的岗位调研，再生成课程计划，最后运行此每日更新。已有目标岗位作为更新索引；检查相关 JD 的变化和缺口，不每天重建整套岗位库。豆包补资料不能替代招聘原始要求。

## 顺序和日记录

1. 用用户当地日期读取当天计划、已有资料、版本和缺口；联网查当天课程所需的原始来源、更新与相关变化。经典基础不硬加年份。查阅日期不等于资料发布日期；无新变化也是有效结果，保留执行查询及已读范围。
2. 再让用户豆包处理相关文章、公众号和视频，补案例、解释、不同观点与可能遗漏。本机用户已指定豆包桌面端，先读 [doubao-desktop.md](doubao-desktop.md)，复用已登录的桌面应用；其他环境先发现可用连接工具，未连接时再使用可用 UI。没有会话就打开官方入口检查，登录、验证码、权限等由适当的用户流程完成，不声称代登录成功，不用火山引擎 API 冒充用户的豆包。
3. 读回豆包结果，追到文章正文、公众号原文、视频原页及字幕／时间戳核对。豆包回答本身是二次生成的候选，不能作为原始来源，也不能与其引用的论文算两份独立证据。逐项核对标题、作者和 URL；仅有豆包“已观看”声明，拿不到实际字幕或观看依据时，不把视频时间戳视为已核对。无法读正文或视频的部分标为 partial 或 blocked，不补造标题、链接、转写或时间戳。
4. 将核对后的增量变成可教知识点，说明“新增／修正／未变化／暂未证实”，只改受影响的未来课次；保留旧知识包、题库、真实成绩与变更理由。导出新知识包时用新的 revision 目录，运行原有校验。

当天日志放在 `research/daily/YYYY-MM-DD/`，包含 `联网核对.md`、`豆包任务.md`、`豆包返回.md`（实际收到才建）和 `知识增量.md`。日志记录时间、任务范围、查询、原始链接、日期／版本、读到哪里、关键定位、与现有结论的关系、采纳与排除理由。三类补充的 channel 分别是 article、wechat、video；没有找到或无法访问时也逐类记录，不用空白充覆盖。

同一天提前学习下一课程单元，复用今天已核对范围，缺少新单元所需资料再补查；不会因课程编号从 L01 变 L02 就伪造第二个日期。另一天开始再重新联网检查。基础学科记录 refresh=not-required 即可，不强制做空的豆包任务。

## 给豆包的任务模板

只发送本次公开主题、课程目标、公开链接和资料缺口；不自动发送用户诊断原话、简历、私有文件、完整学习状态或音频。用户特意要求传具体私有资料时按实际授权处理。把以下内容替换为真实主题与日期后再发送：

> 请为【主题／用途】在【实际日期】的【课程单元】补充学习资料。先围绕这些知识点与缺口：【列表】。请分别查找和阅读相关公开文章、微信公众号原文和视频；优先原作者／机构，时效范围为【与主题相符的窗口】，经典解释可以不限日期。每条列出类型、标题、作者／机构、原始 URL、发布或更新日期（未知就写未知）、真正读到的范围，以及可核对的段落／页码／视频时间戳。提取知识点、例子、常见误区、适用条件和与现有资料不同的观点；明确区分原文事实和你的总结。视频仅有标题或摘要时明确说未观看，无法访问、没找到的类别说明原因，不编造链接或时间戳。最后列出仍待核实的问题。不要替学习者生成作答或成绩。

批次先聚焦当天必需的少量资料。豆包未返回、登录失败或同一步连续两次不能推进时记录具体阻碍，保存已准备好的任务，不无限重试。同一任务已有返回则复用，不反复发送。

## 状态与继续学习

- complete：当天联网已执行并有阅读日志；豆包已实际返回，相关补充核对完，三类材料覆盖或未覆盖原因明确。没有新知识也可完成。
- partial：已有部分核对，但豆包登录／读取、某类来源或新增事实尚受限。写清阻碍、已经核对的范围和下一步。
- failed：当天联网或来源访问失败；保存实际失败记录，不能写“已查最新”。
- not-required：基础学科每日例行更新不适用。

受限时可以用已有稳定且核对过的材料继续已授权教学；受限制的新结论留 blocked，资料更新不能被宣称全部完成。不得因为豆包不可用就让用户必须重建整套课程。后续恢复连接时补回任务和核对，保留先前限制记录。
