# 从关键词到教学

关键词输入、缺少资料或接收研究交接时读取。

## 一次输入运行两个 skill

`$learning-skill RAG`，或在已表明学习意图的对话中直接输入 RAG，进入同一流程：解析关键词 → 检索阅读 → 提取知识点与证据 → 核对可教范围 → 一道诊断题 → 按真实回答教学。这由模型选择并执行 skills，不是后台服务。

先从可用 skills 找 knowledge-research 并读取其 SKILL.md；同级安装时位于 ../knowledge-research/SKILL.md。统一把学习文件放在 learning-workspace/<主题>/，研究结果放在 research 子目录。已有资料和记录优先复用。

## 接收知识包

读取 handoff.json、knowledge-packet.json 和首课相关明细。确认脚本验证过引用与依赖，人工再核对陈述、证据和条件。只教 ready；blocked 写为待查。进阶缺口不妨碍基础教学，影响首个核心任务的缺口则先补查。版本不明先教稳定概念，不声称代码示例已经运行。

研究 skill 不可用时，用当前联网工具按同样的来源要求建轻量知识包，继续第一道诊断。联网不可用时利用明确已有资料并说明限制，不能伪造检索成功，也不强制额外服务。

## 没有问卷也能开始

仅关键词时可按中文、首轮 30 分钟、完成一个小任务推进，明确这是可调整假设。未知水平保持待诊断；宽主题先给领域地图，首课只选基础模块。不因缺少总时长而停在方案。

从 handoff 选一道能区分理解的题，现场只呈现这一题，等回答后反馈。不把知识解释、卡片答案和量表要点与诊断题一起贴出。用户明确要答案或直接讲解时尊重其选择。

## 保存与续学

学习入口记录来源、范围、诊断状态、首课任务和下一步。研究导出的 cards.json 交给 practice.py；初始化不生成成绩，真实作答后才更新复习。新主题单独建状态，不与首次学习方法题库混在一起。

记录每次涉及的知识点 ID 与实际来源。用户回答暴露资料缺口时定向补查；只是理解不足时直接教学，不把每次错误都变成全网重搜。新版本题库保留旧记录，不覆盖历史。
